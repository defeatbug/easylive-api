# 会影响「界面上出现什么」的开关

> 这份清单是为了解决一类反复出现的问题：**界面元素不见了，而原因是某个环境变量没设。**
> 判断标准只有一条 —— 一个开关如果能让用户看不到/用不了某个功能，
> 它就必须 (1) **默认站在功能可用的一侧**，(2) 在**启动日志**里明说，
> 因为排查的人一定会看日志，但不会去读接口响应。

## 原则

1. **默认可用**：功能开关的默认值应当是"功能能用"。要让功能消失，必须显式关掉它。
   反例（都已修）：
   - `SIGNUP_ENABLED` 默认 `false` → 注册页做好了却看不到注册按钮，只好去读 `/auth/capabilities` 才能查出来；
     这个开关已**整个删除**，注册现在跟随鉴权开关。
   - `RECORD_ENABLED` 默认 `false` → 录制是核心功能，默认关闭会表现为"主持人在菜单里看得到录制、
     一按就失败"。现在**默认开启**，要关请显式设 `RECORD_ENABLED=false`。
2. **结论写进启动日志**：不确定"为什么没有某个按钮"时，先看服务启动那几行。
3. **不要用一个开关同时控制"能不能做"和"要不要显示"**：安全开关不该兼职做 UI 开关
   （这正是 `SIGNUP_ENABLED` 的问题）。

## 清单

| 开关 | 默认 | 关掉/改掉之后，界面上会怎样 | 说明 |
|---|---|---|---|
| `AUTH_MODE` | 开发 `off`，非开发 `required` | `off` → **没有登录页**，以访客身份直接入会（`/auth/login` 返回 501） | **刻意如此**：这是安全模式，不是 UI 开关。启动日志会明确说"登录功能已关闭" |
| `RECORD_ENABLED` | **开** | 关 → 主持人**看得到**「录制」菜单但点不动 | 已改为默认开启；启动日志会报"会议录制=开/关" |
| `METRICS_INTERVAL` | `5s`（开） | `0` → `#/metrics` 能打开，但**历史曲线是空的** | 启动日志会报"报表数据=开/关" |
| `AUTO_MIGRATE` | 开 | 关 → 若库里还没有表，**登录与注册都会失败** | 启动日志会报"自动迁移=开/关" |
| `ENABLE_DEBUG_ENDPOINT` | 关闭 | 无界面影响（只影响调试接口是否存在） | 无需处理 |
| `WHITEBOARD` / 虚拟背景 / 聊天 | 无开关 | — | 这些功能没有环境变量控制，始终可用 |
| `WS_MAX_CONNECTIONS` / `ROOM_MAX_PARTICIPANTS` / 各类 TTL | 有业务默认值 | 无界面影响（到限制时会给出明确错误） | 无需处理 |
| 前端 `DSH_API_TARGET`（仅开发期） | `http://localhost:8080` | 指错 → 页面接口全 404 | 开发期代理目标，只影响本地开发 |

## 怎么快速自查

```bash
# 1) 服务端"这个部署能做什么"（前端据此决定要不要显示登录/注册入口）
curl -s localhost:8080/auth/capabilities
# {"authEnabled":true,"signupEnabled":true}

# 2) 启动日志里集中报出的界面能力（有/没有某个按钮先看这里）
go run . 2>&1 | grep -E "界面能力|登录功能|自助注册"
```

## 新增开关时的检查清单

- [ ] 默认值是否让功能**可用**？（除非它是安全开关，且默认关闭是刻意的）
- [ ] 关闭时**启动日志**有没有一行说明后果？
- [ ] 它会不会同时改变 UI 的显示？如果是，前端是**怎么知道的**（接口字段？grant？），
      不要让它靠猜。
- [ ] 写进本文件。
